# 易错点与调试

MJCF 的问题分布在三个时刻：编译期、加载后覆盖、运行时物理。三个时刻的修法不同，先判定时刻再看段，能把排查范围缩小一半。反过来先改 XML 再发现是 Python 覆盖，或者先调求解器再发现 floor 被改了名字，都会白跑一轮。

按症状先判定出问题的时刻，能把排查范围缩小一半；最小编译自检脚本要打印哪些字段，就是判定时刻的依据。三处最常改错的位置分别是 XML 写错、加载后被 Python 覆盖与运行时物理异常，各自的验证方式不同。

> 调试对象是 `models/go1/` 下的三份 XML 与 `envs/go1_walk.py` 的加载、覆盖、reset 段；探针在 `sim/` 下，历史现象记在 `docs/experiment-log.md`。

## 1. 按三个时刻分层定位

| 症状 | 首查时刻 | 首查对象 |
| --- | --- | --- |
| 加载报错或找不到资产 | 编译期 | include 路径、meshdir、assets 字典 |
| 参数与 XML 不符 | 加载后覆盖 | `envs/go1_walk.py` 的 opt/geom 赋值 |
| 观测维度或接触数异常 | 运行时 | sensor 段、njmax/naconmax |
| 策略行为与训练档不符 | 运行时 | 场景选择、软硬接触开关 |
| 出生点穿地或悬空 | 编译期加运行时 | hfield 的 pos.z 与 keyframe |

判定时刻的依据是 MjModel 是否已经建立。编译期错误来自 XML 本身；MjModel 一旦建成，XML 的改动就不再生效，剩下的现象都来自 Python 侧或物理求解。观测维度 48、83、91 三档由场景与 height_scan 开关组合决定，属于运行时（`envs/go1_walk.py`）。

## 2. 编译自检脚本要打印什么

排查顺序是先复现编译，再打印编译结果，最后看物理。一个最小的编译自检：

```python
import mujoco
m = mujoco.MjModel.from_xml_path("models/go1/scene_mjx_position.xml")
print(m.nq, m.nv, m.nu, m.njnt, m.nbody, m.ngeom, m.nsensor, m.nkey)
print(m.opt.cone, m.opt.impratio, m.opt.timestep)
print(m.actuator_gainprm[:2], m.actuator_biasprm[:2])
gid = m.geom("FR").id
print(m.geom_condim[gid], m.geom_solimp[gid][:3], m.geom_friction[gid])
print(m.geom_priority[m.geom("floor").id])
````

| 打印项 | 能回答的问题 |
| --- | --- |
| `nq / nv / nu / njnt / ngeom / nsensor` | 结构、执行器、几何、传感器数量是否符合预期 |
| `opt.cone / impratio / timestep` | option 段与运行期覆盖是否生效 |
| `actuator_gainprm / biasprm` | 位置伺服是否来自 go1 基类的 kp 与 kv |
| `geom_condim / solimp / friction` | 足端子类覆盖与运行期软接触开关 |
| `geom_priority` | 足-地接触参数按哪一侧整组取 |

这套输出能回答大多数参数问题。它与训练无关，不需要 GPU，几秒钟就能跑完，应当在改动 XML 之后先跑一遍。

## 3. 调试工具链与顺序

```mermaid
flowchart TD
  A["症状"] --> B{"XML 能编译吗"}
  B -->|否| C["查 include 与 meshdir 与 assets 字典与 floor 名"]
  B -->|是| D{"MjModel 字段符合预期吗"}
  D -->|否| E["查 default 继承与 autolimits，再查 Python 覆盖"]
  D -->|是| F{"物理或观测异常吗"}
  F -->|"NaN 或接触溢出"| G["查 njmax 与 naconmax 与求解器迭代"]
  F -->|"行为不符"| H["查场景选择与软硬接触与 keyframe 与动作语义"]
  F -->|"出生异常"| I["查 hfield 的 pos.z 与 reset"]
````

```mermaid
sequenceDiagram
  autonumber
  participant D as 调试者
  participant M as MjModel
  participant P as 探针 sim 目录
  participant L as experiment-log
  D->>M: from_xml_path 复现编译
  M-->>D: 维度与参数
  D->>M: 对照 XML 与参考仓库
  D->>P: probe_nefc 与 probe_standability 与 view_go1
  P-->>D: 接触数、站立高度、逐帧行为
  D->>L: 对照历史现象与判据
````

运行时的接触容量由 `envs/go1_walk.py` 的两个配置决定：`naconmax` 是所有 world 共享的接触槽总数（默认 `8*8192`），`njmax` 是单个 world 的约束行上限（256）。`sim/probe_nefc.py` 专测 njmax 溢出，属于约束预算那一单元的范围。

工具链里最后一步常被跳过：对照历史记录。`docs/experiment-log.md` 里记着此前同类现象已经排除的原因，先读一遍可以避免重复验证。

## 4. 常见问题清单

| 现象 | 原因 | 位置 |
| --- | --- | --- |
| `unrecognized name 'floor'` | 单独编译主体 XML，接触传感器找不到 floor | `models/go1/go1_mjx_position.xml` |
| 足-地接触 condim 与摩擦被改 | floor 的 priority 写成 1，两侧同级取最大值 | `scene_mjx_terrain.xml` |
| 足端接触信号全断 | floor 被改名 | `scene_mjx_terrain.xml` |
| 改了 XML 参数行为不变 | MjModel 建成后 Python 又覆盖 | `envs/go1_walk.py` |
| 关节参数与元素行不一致 | default 继承与 autolimits | `models/go1/go1_mjx_position.xml` |
| 观测维度 48/83/91 不符 | 场景与 height_scan 开关组合 | `envs/go1_walk.py` |
| 出生穿地或悬空 | hfield 的 pos.z 未随地形重标 | `scene_mjx_terrain.xml` |
| 高台阶上拖地不罚 | 奖励用绝对足端 z | `envs/go1_walk.py` |
| JIT 内找不到 STL 或 PNG | assets 字典漏收目录 | `envs/go1_walk.py` |
| 训练 NaN | 求解器迭代与接触容量不匹配 | `envs/go1_walk.py,92-96` |
| 改地形分辨率后接触被截断 | 每对 geom-hfield 上限 50，静默溢出 | `scene_mjx_terrain.xml` |
| 传感器读数错位 | 按 sensordata 下标硬取 | `envs/go1_walk.py` |

逐条定位时，先打印编译结果，再决定改 XML 还是改 Python。XML 只影响新编译的 MjModel；已经训练过的策略吃的是旧物理，二者不能混用。

## 5. 易错点

| 易错点 | 现象 | 对应位置 |
| --- | --- | --- |
| 把 floor 当普通 geom 改名 | 接触传感器与奖励一起失效 | `models/go1/go1_mjx_position.xml` |
| 改 priority 不看接触规则 | condim 3、摩擦 1.0，抓地语义变 | `scene_mjx_terrain.xml` |
| 只在 XML 调参数 | 运行期覆盖把值改回 | `envs/go1_walk.py` |
| 用绝对 z 写地形判据 | 高台上判据失真 | `envs/go1_walk.py` |
| 复现实验只带 PNG | 档位信息丢失 | `models/go1/assets/terrain.json` |
| 忽略 keyframe 与 body pos 的区别 | 改 XML 的 z 出生点没变 | `envs/go1_walk.py` |
| 用平地策略跑地形场景 | 物理与观测都不一致 | `sim/view_go1.py` |
| 看到 NaN 只回填 qpos/qvel | 奖励仍读到非有限值 | `envs/go1_walk.py` |
| 排查时不先看编译结果 | 实际生效的是 env 覆盖值 | `envs/go1_walk.py` |

## 6. 观测维度三档的对齐检查

观测维度 48、83、91 三档来自同一份 obs 组装函数在不同开关组合下的三个结果。排查维度不符时按三步走：

1. 确认场景选择是平地还是地形（`envs/go1_walk.py`）；
2. 确认 height_scan 一类开关是否与训练时一致；
3. 打印策略输入层形状与 env 的 observation_size 对照。

策略加载时会用第一层 kernel 的形状反推 obs 维度，维度不符直接报形状错误。因此“切场景却沿用平地策略”表现为加载失败，比行为异常更容易定位。三档的具体组成见观测空间设计单元，本页只给排查取向。

## 7. NaN 护栏不能只回填状态

`envs/go1_walk.py` 的 NaN 护栏在检测到非有限值后回填 qpos/qvel，但奖励已经在同一子步里读到非有限值。护栏能防止仿真继续发散，不能把这一步的回报纠正回来。

排查顺序因此是：先确认 NaN 的来源（求解器迭代与接触容量，见 `envs/go1_walk.py,92-96`），再去调回填逻辑。只加护栏不改来源，会得到“训练不崩但奖励里夹着一批异常值”。

## 8. 资产路径的三处核对

| 环节 | 要核对什么 | 位置 |
| --- | --- | --- |
| 编译 | include 相对路径与 `meshdir` | `models/go1/go1_mjx_position.xml` |
| 打包 | `update_assets` 是否含整个 `assets/` 目录 | `envs/go1_walk.py` |
| 复现 | PNG 与 `terrain.json` 成对复制 | `models/go1/assets/terrain.json` |

三处核对都只依赖文件系统，不需要启动仿真，适合放进交付前的检查清单。

三处任一处缺失的表现不同：编译期缺 include 会直接报错，打包缺目录只在 JIT 内报找不到文件，复现缺 json 则表现为地形档位对不上而没有任何报错。

## 9. 三处最常改错的位置

| 位置 | 常见改法 | 正确做法 | 验证方式 |
| --- | --- | --- | --- |
| `envs/go1_walk.py` 软接触覆盖 | 在 XML 里改 solimp | 改代码里的 `geom_solimp` 与 `geom_condim`，两套参数成对切换 | 重新编译 MjModel，打印足端 `geom_solimp` |
| `scene_mjx_terrain.xml` 地形标定 | 改 PNG 后不动 pos.z | 按新的 `elevation_z` 与 `base_z` 重标 geom 高度 | 让机器人自由沉降，看稳定高度是否与平地一致 |
| `envs/go1_walk.py` reset | 改 body 的 pos 期望出生点变化 | 改 keyframe 与 reset 覆盖逻辑 | 打印 reset 后 `qpos[2]` 与稳定值 |

三处的共同点是"改了一处，另一处仍在生效"。验证的方式都落在重新编译模型或打印运行时状态上，而不是读 XML。

## 10. 小结

### 核心概念

1. 先判定问题在编译期、加载后覆盖还是运行时物理，再选查哪一段。
2. 编译自检脚本打印维度、opt、gainprm/biasprm、geom 接触参数与 priority。
3. floor 是最多接口绑定的 geom：接触传感器、priority、地形类型都指向它。
4. XML 只决定新编译的 MjModel，训练好的策略不会随 XML 改变。
5. 接触容量与求解器迭代属于运行期配置，与模型结构分开排查。
6. 历史记录先读一遍，避免重复验证已经排除的原因。

### 设计权衡

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 参数写在 XML | 单一来源，可复现 | 编译后不可热改，需重新加载 |
| 参数在 env 里覆盖 | 同一模型跑软硬两套物理 | 实际生效值不在 XML 里，易误判 |
| 用探针脚本定位 | 量化接触数、沉降、站立高度 | 需要额外运行时间与 GPU 资源 |

## 11. 练习

### 基础题

1. 编译 `models/go1/scene_mjx_position.xml`，打印 `nq`、`nv`、`nu`、`njnt`、`ngeom`，并说明 $nq \ne nv$ 的原因与 freejoint 在 qpos 中的切片。
2. 从编译结果里读出足端 geom `FR` 的 `condim`、`solimp`、`friction` 与 `floor` 的 `priority`，据此写出足-地接触实际生效的摩擦三项，并指出这是哪条规则决定的。
3. 解释 `keyframe("home").qpos` 的 19 个分量如何分配，以及 `envs/go1_walk.py` 的 reset 覆盖了其中哪些、保留哪些。

### 挑战题

4. 把 `models/go1/scene_mjx_position.xml` 的 floor 改成 `models/go1/scene_mjx_terrain.xml` 那样的 hfield，同时保持出生高度与平地一致。要求给出：hfield 的 `size` 四项各取什么、geom 的 `pos.z` 如何确定、四个 `*_floor_found` 传感器是否仍然有效，以及用哪个探针或脚本验证对齐（提示：`sim/gen_terrain.py` 的同步逻辑与 `scene_mjx_terrain.xml` 的标定说明）。
5. 给出一个只跑编译自检、不启动训练的回归脚本，列出它要断言的字段与每项判据，并说明它能拦住哪三类改动引入的错误。
