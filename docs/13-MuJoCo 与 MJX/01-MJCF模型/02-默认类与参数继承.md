# 默认类与参数继承

MJCF 的 `default` 段定义参数模板，`class` 属性把模板挂到具体元素上。模板不产生运行时字段，编译期把每个元素的字段补全后才写入 MjModel。四足模型有 12 个结构相同的铰链与 56 个 geom，逐元素写全会让"改一个参数"变成改十几处，default 树解决的正是这个问题。

默认类与实例谁覆盖谁，是这份继承规则里最容易记反的一条；`autolimits` 让 `limited` 由 `range` 推断，则说明 XML 里写的值不一定是编译后的值。把一条小腿关节的每项字段追到来源行，再对照本项目、参考仓库与 menagerie 三个版本，能看出哪些差异来自 default 树、哪些来自加载后的覆盖。

> 继承规则写在 `models/go1/go1_mjx_position.xml:22-83` 的 `<default>` 树里；对照版本在 `unitree_go1/go1_position.xml`、`unitree_go1/go1_torque.xml` 与 menagerie 的 `unitree_go1/go1.xml`。

## 1. default 是编译期的参数模板

| 层面 | 写法 | 作用范围 |
| --- | --- | --- |
| 顶层 default | `<default class="go1">...</default>` | 显式引用该类的元素 |
| 子类 default | 嵌套在类里的 `<default class="knee">` | 引用 `class="knee"` 的元素 |
| body 级 childclass | `<body ... childclass="go1">` | 该 body 及其所有后代，除非后代另写 class |

Go1 模型的 default 树按元素类型分支，`knee`、`foot` 这类子类只覆盖少数几项，其余继承 `go1`：

```mermaid
flowchart TD
  G["default class=go1<br/>joint: axis 0 1 0 / damping 1.0 / armature 0.01 / frictionloss 0.1<br/>position: kp 20 / kv 1 / forcerange 正负 23.7"] --> A["abduction<br/>axis 1 0 0 / range 正负 0.863"]
  G --> H["hip<br/>range -0.686 到 4.501"]
  G --> K["knee<br/>range -2.818 到 -0.888 / forcerange 正负 35.55"]
  G --> V["visual<br/>mesh / contype 0 / conaffinity 0 / group 2"]
  G --> C["collision<br/>capsule / group 3"]
  C --> F["foot<br/>sphere 0.023 / condim 6 / solimp 0.015 1 0.031<br/>priority 1 / friction 0.6 0.02 0.01"]
````

default 树的结构与元素类型一一对应：`joint`、`geom`、`site`、`position` 各有自己的模板分支，`foot` 挂在 `geom` 下而不是并列。写错了嵌套层级，元素拿不到预期参数，编译却不会报错。

## 2. 取值优先级与 childclass

编译单个元素时的取值优先级，从高到低：

1. 元素自身的属性，例如 `<joint class="knee" ... forcerange="...">` 里直接写的值。
2. 元素 `class` 指向的 default 里对应元素类型的属性。
3. 该 class 的祖先 default。
4. MuJoCo 内置默认值。

```mermaid
flowchart TD
  A["元素属性"] -->|未写| B["class 指向的 default"]
  B -->|未写| C["祖先 class default"]
  C -->|未写| D["编译器内置默认"]
  A --> E["写入 MjModel 字段"]
  B --> E
  C --> E
  D --> E
```

嵌套的 `default` 按 XML 树继承：子类自动继承父类的全部属性，再覆盖自己写出的项。同一个 `default` 树里类名必须唯一，跨段重名会让后者覆盖前者，编译不报错。

`childclass` 把默认模板一次性挂给整棵子树。`models/go1/go1_mjx_position.xml:96` 的 `childclass="go1"` 让 trunk 之下所有 body 默认走 `go1` 模板，四条腿的关节与 geom 因此共享同一套公共参数。后代若显式写了 `class`，以显式值为准。

## 3. 逐项展开：一条小腿关节的每个字段来自哪

以 `FR_calf_joint` 为例，编译后的每个字段来自哪一层可以逐项核对：

| 字段 | 值 | 来源层 |
| --- | --- | --- |
| `axis` | 0 1 0 | go1 基类第 24 行 |
| `damping` | 1.0 | go1 基类第 24 行 |
| `armature` | 0.01 | go1 基类第 24 行 |
| `frictionloss` | 0.1 | go1 基类第 24 行 |
| `range` | -2.818 -0.888 | knee 子类第 35 行 |
| `limited` | 真 | autolimits 由 range 推断 |
| 执行器 `forcerange` | -35.55 35.55 | knee 子类第 36 行 |
| 执行器 `ctrlrange` | -2.818 -0.888 | knee 子类第 36 行 |
| 执行器 `kp` / `kv` | 20 / 1 | go1 基类第 25 行 |

四条腿共用同一模板，改一个数值就同时改动 FR/FL/RR/RL 的对应关节。12 个关节里只有 `range` 与 `forcerange` 需要按腿区分，其余共用，这是选择 default 而非逐元素书写的主要原因。

`autolimits="true"`（`models/go1/go1_mjx_position.xml:18`）把 `limited` 属性交给编译器推断：写了 `range` 就是有限位，没写就是无限位。因此 XML 里只写 `range="-0.863 0.863"` 而不写 `limited="true"`。编译后实测 `jnt_limited` 对 12 个铰链全为真。

## 4. 三个 Go1 版本的参数差异

数值来自编译后的 MjModel：

| 参数 | 本项目 `go1_mjx_position.xml` | 参考仓库 position 模型 | menagerie `go1.xml` |
| --- | --- | --- | --- |
| 基类 `position` | kp 20 / kv 1 | kp 20 / kv 1 | kp 100 / 无 kv |
| 基类 `joint` damping | 1.0 | 1.0 | 2.0 |
| 基类 `joint` frictionloss | 0.1 | 0.1 | 0.2 |
| abduction 类 damping | 继承 1.0 | 继承 1.0 | 覆盖为 1.0 |
| 足端 solimp | 0.015 1 0.031 | 0.015 1 0.031 | 0.015 1 0.023 |
| 足端 friction | 0.6 0.02 0.01 | 0.6 0.02 0.01 | 0.8 0.02 0.01 |
| 基类 `geom` condim | 未写，编译为 3 | 第 8 行注释掉 | 生效 `condim="1"` |
| 材质 dark | rgba 0.1 | rgba 0.1 | rgba 0.2 |
| home qpos z | 0.35 | 0.35 | 0.27 |

参考仓库的 torque 模型又是另一套：`position` 缺省变成纯力矩执行器（gainprm 1、biasprm 全 0），足端 `friction="2.0 0.02 0.01"`（`unitree_go1/go1_torque.xml:9-12,66`）。

三个版本里最容易被忽略的差异是 kp：menagerie 的 100 是参考仓库与本项目的五倍，换模型却不换策略时，同样的动作目标会产生完全不同的力矩量级。对照实验前先把这张表逐项确认。

## 5. 本工程 Go1 的 default 树落点

| 位置 | 内容 | 与原理的对应 |
| --- | --- | --- |
| `models/go1/go1_mjx_position.xml:24` | `<joint axis="0 1 0" damping="1.0" armature="0.01" frictionloss="0.1"/>` | 基类给所有铰链的公共动力学参数 |
| `models/go1/go1_mjx_position.xml:25` | `<position kp="20" kv="1" forcerange="-23.7 23.7"/>` | 位置伺服基类 |
| `models/go1/go1_mjx_position.xml:26-29` | abduction 覆盖 axis 与 range | 外展关节绕 x 轴，行程正负 0.863 |
| `models/go1/go1_mjx_position.xml:30-33` | hip 覆盖 range | 大腿行程 -0.686 到 4.501 |
| `models/go1/go1_mjx_position.xml:34-37` | knee 覆盖 range 与 forcerange | 小腿行程 -2.818 到 -0.888，力矩正负 35.55 |
| `models/go1/go1_mjx_position.xml:38-40` | visual 类 `contype=0 conaffinity=0 group=2` | 外观网格不参与碰撞 |
| `models/go1/go1_mjx_position.xml:41-81` | collision 类与 hip/thigh/calf/foot 子类 | 碰撞几何复用同一套模板 |
| `models/go1/go1_mjx_position.xml:76-80` | foot 覆盖 condim/solimp/friction/priority | 足端接触参数的最终来源 |
| `models/go1/go1_mjx_position.xml:96` | `childclass="go1"` | 整棵 body 树默认走 go1 模板 |
| `envs/go1_walk.py:434-438` | 直接把 `geom_solimp` / `geom_condim` 写回 MjModel | default 是编译期输入，编译后仍可覆盖 |
| `envs/go1_walk.py:476-483` | 由 `actuator_ctrlrange` 算内缩 5% 的软限位 | ctrlrange 的运行时用途 |

`envs/go1_walk.py:436-438` 把四个足端的 `solimp` 改成 `[0.9, 0.95, 0.023, 0.5, 2.0]` 并把 `condim` 改成 3，对应软接触训练档；`foot_soft_contact=False` 时保留 XML 的硬接触。`envs/go1_getup.py:119-125` 则从 `jnt_range` 取限位，再把软限位算成中心正负 0.5×range×0.95，说明 default 里的 `range` 会一路传到奖励函数。

default 与 autolimits 的组合让改一个数值就影响全体同类元素，代价是单个关节的实际取值必须靠编译结果核对，不能只看元素那一行。

## 6. 用编译结果核对 default 展开

default 只在编译期存在，因此核对它必须看 MjModel。下面这段只读脚本可以逐项确认展开是否符合预期：

```python
import mujoco, numpy as np
m = mujoco.MjModel.from_xml_path("models/go1/scene_mjx_position.xml")
print("nq nv nu njnt ngeom", m.nq, m.nv, m.nu, m.njnt, m.ngeom)
print("jnt_limited", m.jnt_limited)
print("jnt_range", m.jnt_range)
print("actuator_gainprm", m.actuator_gainprm[:5])
print("geom_solimp 足端", m.geom_solimp[m.geom("FR").id])
print("geom_condim 足端", m.geom_condim[m.geom("FR").id])
```

| 打印字段 | 用来回答的问题 |
| --- | --- |
| `nq / nv / nu` | 结构与执行器数量是否与预期一致 |
| `jnt_limited / jnt_range` | autolimits 展开是否符合预期 |
| `actuator_gainprm / biasprm` | 位置伺服增益是否来自 go1 基类 |
| `geom_solimp / geom_condim` | 足端子类覆盖是否生效 |
| `geom_contype / conaffinity` | visual 类是否确实退出接触 |

把这张表跑成一条命令，改 XML 之后先看输出再跑训练，可以省掉一整轮训练才发现参数没生效的成本。

## 7. 参数继承相关的故障现象

| 现象 | 原因 | 对应位置 |
| --- | --- | --- |
| 以为 default 有运行时对象 | 在 Python 里找不到 `model.default` | `models/go1/go1_mjx_position.xml:22-83` 只在编译期生效 |
| 子类只写差异项却当成全部覆盖 | knee 的 axis 仍是基类的 `0 1 0` | `models/go1/go1_mjx_position.xml:24,34-37` |
| 漏写 `childclass` | 子 body 拿不到 go1 模板，参数回落到内置默认 | `models/go1/go1_mjx_position.xml:96` |
| 混用 position 与 torque 模型参数 | 用 kp=100 训练后策略换到本项目物理行为变了 | `unitree_go1/go1.xml:10` 与 `models/go1/go1_mjx_position.xml:25` 的差异 |
| 在 XML 改参数后期望策略兼容 | 训练好的 pkl 行为改变 | `envs/go1_walk.py:434-438` 运行期仍会覆盖 |
| 忽略 `autolimits` | 关节没写 `limited` 就以为无限位 | `models/go1/go1_mjx_position.xml:18` 与实测 `jnt_limited` 全真 |
| 直接编译主体 XML | 报 `unrecognized name 'floor'` | `models/go1/go1_mjx_position.xml:241-244` 依赖场景的 floor |
| 把 torque 模型的 friction 2.0 当成本项目值 | 摩擦对照对不上 | `unitree_go1/go1_torque.xml:66` |
| 以为 class 只作用于 body 与 joint | asset 行也带 `class="go1"` | `models/go1/go1_mjx_position.xml:87-91`，本模型无 mesh default，编译值不受影响（推断） |

## 8. 小结

### 核心概念

1. default 是参数模板，编译期展开，没有运行时字段。
2. 取值优先级是元素属性、class default、祖先 default、内置默认。
3. `childclass` 决定整棵子树的默认模板，是 Go1 模型最省重复的写法。
4. `autolimits` 让 `limited` 由 `range` 是否存在推断。
5. 编译后的 MjModel 仍可被 Python 侧改写，XML 不是最终值。

### 设计权衡

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 用 default 集中参数 | 改一处影响全模型，便于对齐参考仓库 | 单个元素覆盖项不直观，需要对照编译结果 |
| 每个元素写全属性 | 读到即所得 | 12 个关节、56 个 geom 重复度高，易漏改 |
