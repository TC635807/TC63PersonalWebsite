# 几何与碰撞参数

georm 段定义几何体，它同时承担两种职责：给渲染用的外观，与给求解器用的碰撞形状。同一根小腿在外观上是一块 STL 网格，在物理上是一段胶囊，两者形状不同、用途不同。用一套 geom 兼任两件事会让渲染精度与碰撞代价绑在一起，因此模型把它们拆成两套。

两套 geom 靠 default 模板与位与过滤器隔离，容器组的归属决定一次改动会影响哪些接触；`condim` 与溶剂参数对应软硬两套物理，改错会让接触从刚性变成可穿透。地形场景的三条硬约束是检验这两件事的边界条件。

> geom 定义在 `models/go1/go1_mjx_position.xml:38-81,101-109,130-131`；地面 geom 在 `scene_mjx_position.xml:23` 与 `scene_mjx_terrain.xml:85-86`；运行期改动在 `envs/go1_walk.py:434-438`。

## 1. 外观与碰撞两套 geom

| 类别 | class | 类型 | contype/conaffinity | group | 用途 |
| --- | --- | --- | --- | --- | --- |
| 外观 | `visual` | mesh | 0 / 0 | 2 | 渲染 |
| 碰撞 | `collision` | capsule / box / cylinder / sphere | 1 / 1 | 3 | 物理接触 |

两套 geom 的位置与尺寸各自独立：外观用 STL 的完整形状，碰撞用简化形体。简化形体的好处是接触计算快且数值稳定，代价是几何误差，因此碰撞体的尺寸要按净空需求单独标定，不能直接取网格包围盒，因此碰撞体的尺寸要按净空需求单独标定，不能直接取网格包围盒。

Go1 编译后 `ngeom=56`。按分组实测：`group=2` 的 13 个是 mesh 外观体，`group=3` 的 42 个是碰撞体，另有地面 1 个。按类型分：mesh 13、capsule 24、cylinder 12、sphere 4、box 2、plane 1。其中 `contype` 与 `conaffinity` 全 0 的正好是那 13 个外观体。

| 分组 | 数量 | 说明 |
| --- | --- | --- |
| `group=2` | 13 | mesh 外观体，不参与接触 |
| `group=3` | 42 | 胶囊、圆柱、盒、球 |
| `group=0` | 1 | 地面 floor |

`group` 只影响查看器里的显示开关，与物理无关。判断一个 geom 是否参与接触要看 `contype/conaffinity`，这一点在下一节展开。

## 2. contype 与 conaffinity 的位与过滤

`contype` 与 `conaffinity` 是按位与的过滤器：接触对 $(a,b)$ 只有在 `contype[a] & conaffinity[b]` 与 `contype[b] & conaffinity[a]` 都非零时才生成。外观网格两值全 0，任何一对都不成立，所以它们只出现在渲染里。

这条过滤发生在宽相之前，因此它的作用不只是"跳过接触计算"：外观几何根本不进入接触候选列表，接触数量与 `naconmax` 的余量也不受它们影响。把外观 geom 的两值写成 1 会让网格参与接触，接触数暴增且数值异常。

碰撞几何用 `fromto` 描述轴向，`autolimits` 编译时把它折算成 `pos` 与 `size`。`fromto` 是书写便利，编译后不再存在；读参数要读 `geom_pos` 与 `geom_size`。

```mermaid

````

## 3. priority 决定接触参数整组归属

接触整组参数包含 `condim`（接触维数）、`friction`（滑动/扭转/滚动三项）、`solref` 与 `solimp`（约束柔度）。足端在 XML 里写 `priority="1"`、地面默认 `priority=0`，于是足-地接触整套取足端的值。

| 规则 | 条件 | 结果 |
| --- | --- | --- |
| 高优先级胜出 | 两侧 priority 不同 | 整套取高的一侧 |
| 逐项最大 | 两侧 priority 相同且非 0 | 每项各取较大值 |
| 默认规则 | 两侧 priority 都为 0 | 每项各取较大值 |

足-地摩擦的实测结果（`docs/experiment-log.md:778-782`）：

| 对象 | 滑动 | 扭转 | 滚动 |
| --- | --- | --- | --- |
| 足端 geom | 0.6 | 0.02 | 0.01 |
| 地面 floor | 1.0 | 0.005 | 0 |
| 足-地实际生效 | 0.6 | 0.02 | 0.01 |

地面自己写 1.0，但足端 `priority=1` 高于地面 0，整组取足端，生效 0.6。参考仓库的 `go1_torque.xml:66` 用 2.0，position 模型用 0.6。

priority 的后果之一是"改地面摩擦不再影响足端"。想让地面摩擦起作用，必须把地面的 priority 提到与足端相同或更高，此时会转为逐项取最大值（`docs/experiment-log.md:1421-1424` 记录了改名与改 priority 的硬约束）。

## 4. condim 与溶剂参数：软硬两套物理

接触维数决定约束的组成：

| condim | 约束 | 典型用途 |
| --- | --- | --- |
| 1 | 法向 | 点接触近似 |
| 3 | 法向 + 两个切向 | 软接触走路 |
| 4 | 3 + 扭转 | 需要抗旋 |
| 6 | 3 + 扭转 + 滚动 2 | 硬接触足端，参考仓库档 |

本项目 XML 的足端是 `condim=6`，运行期软接触档改回 `condim=3`。维数越高，每个接触的约束行越多，`nefc` 与求解时间随之上升；`models/go1/go1_mjx_position.xml:8-10` 的 `iterations` 取值正是为硬接触准备的。

`solimp` 与 `solref` 控制约束的柔度。按 MuJoCo 手册，`solimp` 前三个值是约束阻抗的下界、上界与过渡宽度，`solref` 是时间常数与阻尼比。本项目足端 XML 只写 3 个值 `0.015 1 0.031`；软接触档在代码里写全 5 个值 `0.9 0.95 0.023 0.5 2.0`（`envs/go1_walk.py:437`），前者偏硬、后者偏软，这是两套物理的开关。

只改 `solimp` 不改 `solref` 时，约束的时间常数没变，收敛速度与穿透深度的组合会落在两套物理之间，表现为"看起来软了但抖"。两套参数要成对切换。

```mermaid
sequenceDiagram
  autonumber
  participant X as XML geom
  participant M as MjModel
  participant E as env
  participant S as mjx 求解器
  X->>M: 编译 contype/conaffinity/priority/condim/solimp
  E->>M: 软接触档改写足端 geom_solimp/geom_condim
  E->>S: make_data 时传 njmax / naconmax
  S->>S: 宽相过滤，窄相生成接触，按 priority 取参数
````

碰撞参数的生效结果要看编译后的 MjModel，不能只读 XML 里那一行。priority 让足端整套覆盖地面，contype 让外观体退出接触，autolimits 又改写了 size 字段。

## 6. 地形场景的三条硬约束

| 约束 | 内容 | 位置 |
| --- | --- | --- |
| floor 名字 | 必须叫 floor，接触传感器按名绑定 | `models/go1/go1_mjx_position.xml:241-244`、`scene_mjx_terrain.xml:72` |
| priority | floor 保持 0，足端保持 1 | `scene_mjx_terrain.xml:79-84` |
| 接触上限 | 每对 geom-hfield 接触上限 50，超出静默截断 | `scene_mjx_terrain.xml:18-20` |

三条约束里前两条由传感器与 priority 决定，第三条与地形分辨率耦合。

第三条最隐蔽：分辨率越高的 hfield，足端与地面的接触点越多，超过 50 之后多余接触被丢弃，表现为脚下偶尔踩空或穿地，而日志没有报错。地形分辨率因此不能只按视觉精度选。

## 7. geom 与接触相关的故障现象

| 现象 | 原因 | 对应位置 |
| --- | --- | --- |
| 把 floor 的 priority 写成 1 | 足-地参数变成两侧最大值，实测 condim 3、摩擦 1.0 | `scene_mjx_terrain.xml:79-84` |
| 给 floor 改名 | 四个足端接触传感器全断 | `models/go1/go1_mjx_position.xml:241-244` |
| 把外观 mesh 当碰撞体 | 净空计算被整块网格尺寸污染 | `envs/go1_walk.py:519-523` 显式过滤 |
| 只看 geom 的 pos/size | fromto 已被 autolimits 改写 | `models/go1/go1_mjx_position.xml:62-75` |
| 认为 condim 越大越好 | 硬接触在 MJX 迭代求解器下不收敛 | `models/go1/go1_mjx_position.xml:8-10` |
| 混淆 friction 三项 | 扭转与滚动项写反 | `models/go1/go1_mjx_position.xml:79` |
| 地形分辨率过高 | 每对 geom-hfield 接触上限 50，静默截断 | `scene_mjx_terrain.xml:18-20` |
| 把 group 当物理开关 | group 只影响查看器显示 | `envs/go1_walk.py:518-523` 用 contype 判断 |
| 忽略 solref 只改 solimp | 约束时间常数未变，收敛行为不同 | `envs/go1_walk.py:437` 与 `models/go1/go1_mjx_position.xml:79` |

## 8. 小结

### 核心概念

1. 外观与碰撞用两套 default 模板分开，靠 `contype/conaffinity` 过滤器隔离。
2. 接触对先过位与过滤，再按 `priority` 取参数：两侧不同取高，相同且非 0 取逐项最大值。
3. 足端 `priority=1` 让整套硬接触参数覆盖地面，实测生效摩擦 0.6。
4. `autolimits` 把 `fromto` 折成 `pos`+`size`，读 size 要按 geom 类型解释。
5. 编译后的 geom 参数仍可被 env 覆盖，软/硬接触是运行期开关。
6. floor 的名字与 priority 是传感器与接触参数的接口，不能随意改。

### 设计权衡

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 外观与碰撞分两套 geom | 渲染精度与碰撞代价解耦 | geom 数量翻倍，命名要成对维护 |
| 硬接触 condim 6 加紧 solimp | 与参考仓库逐位一致，抓地强 | MJX 迭代求解器不收敛，需软接触降级 |
| 足端 priority=1 | 足端参数独立于地面 | 地面摩擦改动不再影响足端，容易误判 |

## 9. 练习

基础题

1. 写出 `contype/conaffinity` 的过滤条件，并说明为什么外观网格的两值全 0 就能退出接触。
2. 从编译结果里读出足端 geom `FR` 的 `condim`、`solimp`、`friction` 与 `floor` 的 `priority`，据此写出足-地接触实际生效的摩擦三项。
3. 说明 `fromto` 与编译后的 `pos`+`size` 的关系，以及按 geom 类型读 size 的三套语义。

挑战题

4. 想让地面摩擦从 1.0 开始影响足-地接触。写出需要改动的字段与改动后的取值规则，并说明会连带影响哪些其他接触对。
5. 地形分辨率提高后出现脚下踩空。定位到接触上限的原因并给出两种修法，说明各自的代价。
