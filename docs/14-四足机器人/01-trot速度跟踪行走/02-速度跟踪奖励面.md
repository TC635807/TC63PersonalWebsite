# 速度跟踪奖励面

奖励面写成线性组合：正向塑形项鼓励跟踪速度与正常步态，负向成本项抑制抖动、越界与拖地。

$$r_t = \sum_i w_i \, r_i(s_t, a_t)$$

奖励设计里最难的部分是权重之间的比例与总奖励的截断口径：单项看起来都合理，合起来却可能让总奖励恒为 0，或者让策略发现"站着不动最赚"。

两批权重与总奖励的下限口径要一起看，否则单项权重都合理、合起来总奖励仍可能恒为 0。指数速度跟踪的梯度形状、姿态与动作成本项、有限性检查与截断，决定了哪些项在什么区间起作用。

> 本页对象是 mjx-go1-getup 走路奖励的组合方式与逐项权重，实现在 `envs/go1_walk.py:1166-1620`：`_get_reward` 的分项表、各分项函数，以及 `step` 里的加权求和与下限截断。任务与观测口径见同单元第 1 篇。

## 1. 奖励面的线性组合与下限口径

参考仓库与 SB3 的通用口径是每步把正向与负向分别求和后取 $\max(0, r_{\text{pos}} - c)$，本项目把它等价成"先加权求和再对总量取下限"。走路任务的下限取 0，即总奖励不得为负。

| 口径 | 写法 | 后果 |
| --- | --- | --- |
| 正负分别求和后再截断 | $\max(0, r_{\text{pos}} - c)$ | 需要分别维护两组项 |
| 加权求和后整体截断 | $\mathrm{clip}(\sum w_i r_i, r_{\min}, 10^4)$ | 实现简单，但 $r_{\min}$ 选错就把梯度抹平 |

两种口径在权重配置合适时结果接近，差别体现在失败模式下：整体截断一旦触发，所有分项的区分度同时消失；分别求和至少保留正向项的差异。本项目采用后者，并把 $r_{\min}$ 的取值写进配置。

## 3. 指数速度跟踪的梯度形状

速度跟踪是奖励面的主项。水平分量用指数形式：

$$r_{\text{lin}} = \exp\!\left(-\frac{\| v^{cmd}_{xy} - v_{xy} \|^2}{\sigma}\right),\qquad \sigma = 0.25$$

角速度用同一尺度：

$$r_{\text{ang}} = \exp\!\left(-\frac{(\omega_z^{cmd} - \omega_z)^2}{\sigma}\right)$$

指数形式的梯度随误差变化。误差为 0 时取 1，误差 0.5 m/s 时约 0.37，误差 1.0 m/s 时约 0.018。指令与实际差得远时梯度接近 0，所以策略先学会把速度拉到附近，再精调。这种"近端放大、远端饱和"的塑形比线性误差更适合从随机初始化起步，代价是远离指令时几乎没有拉力。

```mermaid
flowchart TD
  A["速度跟踪误差 e"] --> B{"e 很大吗"}
  B -- "是" --> C["奖励接近 0，梯度接近 0"]
  B -- "否" --> D["奖励接近 1，梯度明显"]
  C --> E["策略先把速度拉到附近"]
  D --> F["策略精调跟踪精度"]
  E --> F
````

水平跟踪按指令坐标系取速度：`frame="body"` 时用机体系线速度的前两维，否则用 `qvel[0:2]`（`envs/go1_walk.py:1213-1229`）。两处共用同一个 $\sigma$ 与权重，因此切换坐标系不需要改奖励配置。

竖直与姿态项是安全约束。竖直速度项取 $v_z^2$，姿态项取机体系重力水平分量平方和：

$$g^{body} = R^{\top} [0,0,-1]^{\top},\qquad c_{\text{ori}} = g_x^2 + g_y^2$$

直立时 $g^{body}\approx[0,0,-1]$，两项接近 0；机身倾斜时增大。这两项不区分倾角方向，只惩罚偏离。

## 4. 姿态与动作成本项

成本项都是平方和形式：

| 成本项 | 取量 | 位置 |
| --- | --- | --- |
| `torque` | `qfrc_actuator[-12:]` 的平方和 | `envs/go1_walk.py:1492` |
| `action_rate` | 本步与上一步动作差平方和 | `envs/go1_walk.py:1495-1498` |
| `joint_limit` | 软上下界越界量线性累计 | `envs/go1_walk.py:1506-1510` |
| `orientation` | 重力水平分量平方和 | `envs/go1_walk.py:1518-1521` |

`_cost_joint_limit` 用执行器 ctrlrange 内缩 5% 得到的软上下界，越界量线性累计。内缩 5% 的作用是让策略在接近行程端点之前就收到信号，而不是等撞到硬限位。

平方和形式的成本对幅度是二次的：动作幅度加倍，成本变四倍。这一点决定了权重不能按"平均偏差"的线性直觉取。

## 5. 总奖励的有限性检查与截断

总奖励在每步结束时做一次下限截断：

$$r_t = \mathrm{clip}\!\left(\sum_i w_i r_i,\; r_{\min},\; 10^4\right),\qquad r_{\min}=0\ \text{(走路)}$$

`step` 里先逐项乘权重，再求和、查有限性、截断：

```python
rewards = {
    k: v * self._config.reward_config.scales[k] for k, v in rewards.items()
}
total = sum(rewards.values())
total = jp.where(jp.isfinite(total), total, 0.0)
reward = jp.clip(total, self._config.reward_clip_min, 10000.0)
```

对应 `envs/go1_walk.py:1024-1030`。有限性检查把 NaN 与 inf 直接换成 0，避免它们污染梯度；截断把负值抬起、把过大正值压住。

下限为 0 的直接后果是负梯度被抹平：一旦所有成本压过正向项，总奖励恒为 0，PPO 拿不到任何区分度。本项目在多个版本里遇到过这个失败模式，起身任务因此把下限改成 $-10^6$（`envs/go1_walk.py:68-73` 的注释记录了这次改动）。

权重表在 `envs/go1_walk.py:108-172`，开关批次的取值由 `train/train_go1.py` 在环境构造前覆盖，例如 `--natural_gait` 把 `feet_slip` 设为 $-0.5$、`feet_height` 设为 $-1.0$（`train/train_go1.py:446-450`）。

奖励每步不乘控制周期 $dt$，与参考仓库的逐步累加语义一致；brax 默认按 $r_t \cdot dt$ 累加，这里显式避开，好让 episode 总量与参考仓库可比（`envs/go1_walk.py:44-46` 的文件头注释说明）。

## 6. 腾空奖励的指令门限

腾空奖励只在指令速度大于 0.1 m/s 时生效，落地帧按累计腾空时长减阈值求和（`envs/go1_walk.py:1231-1246`）。门限的作用是避免站立时的抖动被当成腾空给分；阈值与封顶的取值在参考配方下反而鼓励不抬腿，第 3 篇会展开。

判断一项塑形是否"有方向"可以看它的门控与阈值：没有门控、阈值又偏低的塑形项，通常会在静止姿态上产生非零回报，成为策略退化的入口。

## 7. 权重按量级标定：两个实测例子

开关项的权重不是凭感觉取的，每项都有探针实测。

第一个例子是躯干高度项。它是平方误差语义，线性直觉会差一个数量级：偏差 2 cm 时每步 -0.08，5 cm 时 -0.5，10 cm 时 -2.0（`base_height=-200`）。正常站立时实测平方误差中位数约 $1.9\times10^{-5}$，该项每步约 $-0.0005$，几乎免费；摔倒或拖地时才显著（`train/train_go1.py:517-530`）。若权重取 $-2000$，每步会给到约 $-8.8$，是当时每步正向奖励的 3.6 倍，会把总奖励压到 0（源码注释所述）。

第二个例子是爬升项。它是状态型奖励，站在台顶不动也按当前高度持续给分，所以要守住权重上界：

| 行为 | 每步奖励口径 |
| --- | --- |
| 平地行走 | 约 +1.776 |
| 站着不动且不高 | 约 +0.347 |
| 站台顶且不动 | 0.347 加 $W\times0.30$ |

$W=2$ 时站台顶约 +0.947，是走路的 53%；$W=8$ 时约 +2.747，超过走路，策略会主动退化成站桩。默认取 $W=2$，并用行进门控把静止时的该项归零（`envs/go1_walk.py:1308-1353`、`envs/go1_walk.py:1338-1344`）。

两个例子指向同一条方法：先测出该项在正常行为与病态行为下的量级，再选权重让两者之间的差足以影响梯度，同时不压过主项。`envs/go1_walk.py:284` 的负项封顶是配套手段：深穿透或深蹲时把单项惩罚封住，避免它吃掉全部正向信号。

## 8. 常见错误

| 现象 | 原因 | 对应位置 |
| --- | --- | --- |
| 总奖励恒 0，PPO 无梯度，学不动 | 下限取 0 又加了大权重成本 | `envs/go1_walk.py:1030` |
| 深穿透或深蹲时惩罚吃掉全部正向信号 | 负项封顶缺失 | `envs/go1_walk.py:284` |
| 远端误差主导，初期梯度方向杂乱 | 用线性误差代替指数塑形 | `envs/go1_walk.py:1213-1223` |
| 站立时也在给腾空分，脚乱动 | 忘了腾空奖励的指令门限 | `envs/go1_walk.py:1245` |
| 正常行为被罚穿 | 把权重当线性量标定平方项 | `train/train_go1.py:517-530` |
| 站桩或站着收钱，策略退化 | 状态型奖励不加行进门控 | `envs/go1_walk.py:1338-1344` |
| episode 总量差 50 倍 | 奖励乘了 dt 又想对齐参考仓库 | `envs/go1_walk.py:44-46` |

## 9. 小结

### 核心概念

- 奖励是逐项加权和，走路默认生效的只有速度跟踪、腾空奖励与一组姿态动作成本。
- 速度跟踪用指数塑形，$\sigma=0.25$，近误差梯度大、远误差饱和。
- 总奖励默认下限为 0，负项过强会让梯度归零，这是本项目反复出现的失败模式。
- 每步奖励不乘 $dt$，与参考仓库的 SB3 语义对齐。
- 开关项的权重全部按探针实测标定，平方项要按量级而非线性直觉取。
- 状态型奖励必须配权重上界与行进门控，否则策略会退化成站桩。

### 设计权衡

| 取法 | 采用处 | 代价 |
| --- | --- | --- |
| 指数速度跟踪 | 默认 | 远离指令时拉力接近 0 |
| 总奖励下限 0 | 走路与参考仓库 | 负项压过正项时梯度消失 |
| 保持参考仓库的置零项 | `joint_velocity`、`collision` | 奖励面与参考实现的实际生效部分一致，但留有漏洞 |
| 状态型奖励配上界与门控 | `ascent`、`symmetry`、`body_contact` | 需要额外实测标定权重 |

## 10. 练习

基础题

1. 写出指数速度跟踪的公式，算出误差 0、0.5、1.0 m/s 三点的奖励值，并说明这种塑形在远端的行为。
2. 说明总奖励的两道处理（有限性检查与下限截断）各自防的是什么，并指出走路与起身任务的下限取值。
3. 逐项列出默认生效的 11 个奖励项及其权重，并说明 `joint_velocity` 与 `collision` 置零的原因。

挑战题

4. `base_height` 取 $-200$ 与 $-2000$ 时，分别算出偏差 5 cm 的每步惩罚，并结合站立时的实测平方误差说明哪个会触发总奖励归零。
5. `ascent` 是状态型奖励。推导 $W$ 的上界，使站台顶不动的每步奖励低于平地行走的 +1.776，并说明为什么还要额外加行进门控。
