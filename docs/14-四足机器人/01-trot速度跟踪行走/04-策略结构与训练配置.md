# 策略结构与训练配置

策略是一个多层感知机加一个动作分布。actor 吃 actor 观测，输出 12 维动作的分布参数；critic 吃特权观测，输出标量价值。两者共享同一套训练步，但网络与输入分开。

配置层面的关键分歧在隐层与分布类型：脚本默认的网络比最终策略宽得多，最终走路策略由命令行把隐层覆盖成 128,128。读超参时先确认看到的是脚本默认值还是命令行覆盖值，否则会把两套配置的结论混在一起。

> 本页对象是 mjx-go1-getup 走路策略的网络结构、检查点内容与训练超参，涉及 `train/train_go1.py`、`sim/common.py` 与 `policies/go1_walk_policy.pkl`。PPO 与 GAE 的推导属相邻单元，本页只讲本工程的取值与接口。

## 1. actor 与 critic 的两套网络

| 部分 | 输入 | 隐层 | 输出 | 观测键 |
| --- | --- | --- | --- | --- |
| actor | 91 维 | 128, 128 | 12 维均值加 12 维噪声参数 | `state` |
| critic | 162 维 | 128, 128 | 1 维价值 | `privileged_state` |

两套网络结构相同、宽度相同，差别只在输入维度与输出头。brax 把 actor 与 critic 装在一个 PPO 网络对象里，用 `policy_obs_key` 与 `value_obs_key` 区分各自的输入。这种装法的好处是前向与更新只写一遍；代价是改其中一侧的隐层必须一起改。

## 2. 两套训练分支的对照

训练入口配置两套分支。GPU 默认档用较宽的网络与 silu 激活，SB3 对齐档用 (64,64)、tanh 激活，并把优化制度压到参考仓库的量级。走路最终策略的隐层由命令行覆盖成 128,128。

| 配置 | GPU 默认档 | SB3 对齐档 `--sb3_full` |
| --- | --- | --- |
| 并行环境数 | `--num_envs` 默认 8192 | 768 |
| rollout 展开长度 | 20 | 32 |
| policy/critic 隐层 | 512, 256, 128 | 64, 64 |
| 激活 | silu | tanh |
| 动作分布 | tanh_normal | normal |
| 观测归一化 | 开 | 关 |
| minibatch 数 | 32 | 384 |
| 每批更新次数 | 4 | 10 |
| 折扣 | 0.97 | 0.99 |
| 熵系数 | 1e-2 | 0 |
| 梯度裁剪 | 1.0 | 0.5 |
| PPO 裁剪 | 0.3 | 0.2 |

两个分支的取值在 `train/train_go1.py`（SB3 对齐档）与 `train/train_go1.py`（GPU 默认档）。除表中各项外，两档还差在观测归一化与熵系数上，这两项对梯度尺度的影响不比学习率小。

```mermaid

  A["actor obs 91 维"] --> B["MLP hidden 128 128"]
  B --> C["Dense 均值头 12 维"]
  B --> D["std_param 12 维"]
  C --> E["Normal 分布采样"]
  D --> E
  E --> F["环境内 clip 到 ctrlrange"]
  G["critic obs 162 维"] --> H["MLP hidden 128 128"]
  H --> I["标量价值"]
````

## 3. 动作分布：normal 与 tanh_normal

brax 的 PPO 参数把 actor 与 critic 装在一起。actor 的动作分布有两种：`normal` 用独立可学习的标准差参数，`tanh_normal` 把均值过 tanh 并让标准差由网络输出。当前 pkl 的参数树里有独立的 `std_param`，对应前者，`sim/common.py` 也按 `normal` 重建网络。

前向过程为：

$$\mu = f_\theta(s^{actor}),\qquad \sigma = \text{softplus}(\rho),\qquad a \sim \mathcal{N}(\mu, \sigma^2),\qquad \tilde a = \mathrm{clip}(a, c_{\min}, c_{\max})$$

$\rho$ 是 12 维可学习参数，初始化在 1.0 附近，对应起始标准差约 1。截断发生在环境侧，不改变分布的支撑集，所以 PPO 的对数概率用的是未截断的 $a$。这一点决定了动作被 clip 时概率密度不会坍缩到边界上。

选 `normal` 而非 `tanh_normal` 的直接后果是探索幅度与状态无关：`std_param` 是全局参数，所有观测下噪声尺度相同。SB3 对齐档选它是为了与参考仓库逐位一致，代价是难以在大行程关节上收紧探索。

## 4. 观测归一化统计量为什么还在 pkl 里

观测归一化在 brax 内部用滑动统计量完成，统计量随训练步更新。当前 pkl 的参数字段的第一个元素就是 `RunningStatisticsState`，含 `mean`、`std`、`summed_variance` 与 `count`，对 `state` 与 `privileged_state` 各一份。

走路训练用 SB3 对齐档，配置里 `normalize_observations=False`，所以统计量会保存但不参与前向；brax 训练循环里 `running_statistics.update` 不在归一化开关之内，统计量仍每步更新并随检查点落盘，pkl 里的 mean 与 std 因此非平凡（`train/train_go1.py`）。

这条性质容易误判：看到 pkl 里有 mean/std 就以为推理会自动归一化，实际上推理端读的是网络参数，归一化是否生效由配置决定。加载端要显式按同一配置重建网络。

## 5. brax 的 minibatch 账目

minibatch 的账目按 brax 语义：`batch_size` 是每个 minibatch 的序列数，每条序列展开 `unroll_length` 步，所以一个 minibatch 的转移数是二者之积。GAE 的窗口由 `unroll_length` 决定，SB3 对齐档取 32，受显存限制，比 SB3 的 2048 短。

SB3 对齐档的关键几行：

```python
num_envs = 768
unroll_length = 32
batch_size = 2
minibatches = 384
updates_per_batch = 10
```

一个训练步的样本数是 $768 \times 32 = 24576$，minibatch 转移数是 $2 \times 32 = 64$，梯度更新是 $384 \times 10 = 3840$ 次，与参考仓库的 SB3 配置对齐（`train/train_go1.py`）。把 `batch_size=2` 误读成"每批 2 条转移"会让每样本更新密度差 32 倍（`train/train_go1.py`）。

## 6. 训练超参的组装点

`ppo_params` 在 `train/train_go1.py` 组装，网络工厂在 `train/train_go1.py` 指定四个键：policy 与 value 的隐层、两个观测键、分布类型与激活。这四组键就是网络结构的全部来源，其余超参只影响优化过程。

超参的覆盖顺序是脚本默认、分支档、命令行。查看某个训练实际用了什么，最快的办法是读实验记录里的完整命令行，而不是读脚本默认值。

## 7. 检查点与 pkl 的两种落盘格式

训练过程写 orbax 检查点目录，目录里有网络配置 json；训练结束后把参数字典单独 pickle 成 `policies/*.pkl`。加载端从参数形状反推隐层宽度与观测维度，因此两种格式都能读。

```mermaid
sequenceDiagram
  autonumber
  participant S as train_go1.py
  participant B as brax PPO
  participant O as logs 与 checkpoints
  participant P as policies pkl
  S->>B: ppo.train 环境 超参 network_factory
  loop 每次评估
    B->>O: 保存检查点与 ppo_network_config.json
    B-->>S: progress 回调打印 eval_reward
  end
  B-->>S: 返回 normalizer policy value 三元组
  S->>P: pickle.dump 参数
````

当前 `policies/go1_walk_policy.pkl` 是一个三元组，从参数形状可直接读出网络尺寸：

| 元素 | 内容 | 形状 |
| --- | --- | --- |
| 第 0 项 | `RunningStatisticsState` | `state` 与 `privileged_state` 的 mean/std/count |
| 第 1 项 | policy 参数 | `MLP_0.hidden_0` 91×128，`hidden_1` 128×128，`Dense_0` 128×12，`std_param` 12 |
| 第 2 项 | value 参数 | `hidden_0` 162×128，`hidden_1` 128×128，`hidden_2` 128×1 |

统计量里的 `count` 是 60,162,048，与实验记录里 v23 的最佳检查点步数一致，可以当作该文件来源的旁证。

## 8. 加载与维度反推

`sim/common.py` 的 `load_policy` 分两条路：目录走 orbax 并读 json 配置，pkl 走 pickle 并硬编码 12 维动作与 `normal` 分布（`sim/common.py`）。维度与隐层由 `infer_layers_and_dims` 从 kernel 形状反推（`sim/common.py`）：

```python
net = ppo_networks.make_ppo_networks(
    observation_size={"state": (ns,), "privileged_state": (nv,)},
    action_size=12, policy_hidden_layer_sizes=layers,
    value_hidden_layer_sizes=layers, policy_obs_key="state",
    value_obs_key="privileged_state", distribution_type="normal",
    activation=jax.nn.tanh)
return ppo_networks.make_inference_fn(net)(params, deterministic=True), ns
```

推理固定用确定性模式，取分布均值，不再采样。这样观察器与评估脚本的逐帧结果可复现。pkl 路径硬编码了 `normal` 分布，用 pkl 加载 `tanh_normal` 训练的网络会因参数树少键而报形状错（`sim/common.py`）。

## 9. 观测维度与网络的耦合

网络输入层形状由环境自动推断，brax 在 `mjx_env.py` 里用 `jax.eval_shape(reset)` 走一遍追踪而不执行计算。改了 `height_scan` 或相位奖励这类会改观测维度的开关，网络宽度随之改变，不需要手改。训练脚本在启动前会打印预期维度并做一次显式核对（`train/train_go1.py`），续训时还会比对检查点 json 里的维度（`train/train_go1.py`）。

维度核对有两层含义：一是训练开始前确认网络输入与环境观测一致，二是续训时确认检查点的维度与当前配置一致。第二层若缺失，会等到参数形状冲突时才报错，而那时已经消耗了加载与编译的时间。

## 10. 常见错误

| 现象 | 原因 | 对应位置 |
| --- | --- | --- |
| 参数树少键，重建网络报形状错 | 用 pkl 加载 tanh_normal 训练的网络 | `sim/common.py` |
| 策略前向在 jit 之前就失败 | 观测维度与网络输入不符 | `train/train_go1.py` |
| 每样本更新密度差 32 倍，学得慢 | 把 brax 的 batch_size 当转移数 | `train/train_go1.py` |
| 检查点读进来后参数形状冲突 | 续训时网络维度变了 | `train/train_go1.py` |
| 以为统计量一定参与前向 | 关归一化时统计量仍保存 | `train/train_go1.py` |
| 产物与日志对不上 | 覆盖隐层后忘记录入实验 | `docs/experiment-log.md` |

## 11. 小结

### 核心概念

- actor 吃 91 维观测、critic 吃 162 维特权观测，各自一套隐层。
- 最终走路策略的隐层是 128,128，由命令行覆盖，不是脚本默认值。
- `normal` 分布用独立可学习标准差，pkl 里能看到 12 维 `std_param`。
- brax 的 `batch_size` 是序列数，转移数要乘 `unroll_length`。
- 检查点与 pkl 是两种落盘格式，加载端从形状反推维度。
- 关掉观测归一化后统计量仍会更新并落盘，但推理不参与前向。

### 设计权衡

| 取法 | 采用处 | 代价 |
| --- | --- | --- |
| 128,128 隐层 | 走路最终版 | 容量小，复杂地形可能不足 |
| normal 分布 | SB3 对齐档与最终策略 | 噪声与状态无关，探索幅度固定 |
| 归一化关 | SB3 对齐档 | 需要自己保证观测量级合理 |
| GAE 窗口 32 | 全部 GPU 训练 | 比 SB3 短，偏置更大 |
