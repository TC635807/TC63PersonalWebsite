# 易错点与调试

调试顺序应当固定：先确认判据，再看数字；先分清是激励问题还是能力问题，再决定加步数还是改奖励面。训练日志里的 `eval/episode_reward` 来自训练同款环境，含随机出生与扰动，不同检查点的出生点不同，数字不能直接比较。

观测面口径与三类失败形态必须分开，否则调参调的是表现而不是原因；速度判据为什么必须转回机体系，决定误判来自坐标系还是来自策略。步态质量的两个统计量与数值问题的排查顺序，是离线评估与交互观察共用的判据。

> 本页对象是 mjx-go1-getup 走路任务的排查方法与易错点，使用 `sim/eval_walk.py`、`sim/watch_v20_fast.py`、`sim/view_go1.py` 与 `envs/go1_walk.py` 的数值护栏。前四篇的背景不再重复。

## 1. 先定判据再看数字

| 观测面 | 指标 | 口径混入的变量 |
| --- | --- | --- |
| 训练日志 | `eval/episode_reward` | 策略变化加出生点运气 |
| 离线评估 | 固定 seed 的 vx_body、跟踪误差、存活率、爬升 | 只反映策略变化 |
| 步态统计 | 四足占空比、对角同步率、触地滑移 | 需要单独脚本或回放 |
| 数值探针 | NaN 环境数、接触约束溢出 | 与策略质量解耦 |

前两行的差别要强调：训练日志的 reward 把"策略变好"与"这次出生的地形更容易"混在一起，跨检查点比较会得出错误趋势。固定 seed 的离线评估把出生点与指令冻结，同一份脚本跑不同检查点，差异才只来自策略。

## 2. 三类失败形态

失败形态按根因分三类：口径类（观测与动作的语义写错）、激励类（奖励面没有区分度或有漏洞）、数值类（NaN、约束溢出、接触不收敛）。三类的排查手段不同，混在一起会浪费时间。

区分的办法是看症状是否与策略质量耦合：固定动作序列就能复现的是数值类，换检查点才变化的是激励类，换成另一个任务同样出错的是口径类。

```mermaid
flowchart TD
  A["现象: 走不动 或 摔倒 或 学不动"] --> B{"训练日志 reward 是否恒 0"}
  B -- "是" --> C["查总奖励截断与负项权重"]
  B -- "否" --> D{"离线固定 seed 的 vx_body 是否接近指令"}
  D -- "否" --> E["查指令坐标系 观测量级 动作语义"]
  D -- "是" --> F{"占空比与对角同步是否合理"}
  F -- "否" --> G["查步态塑形项与抬脚参数"]
  F -- "是" --> H{"是否出现 NaN 或约束溢出"}
  H -- "是" --> I["查 njmax 与 naconmax 与接触模型"]
  H -- "否" --> J["查地形课程与爬升激励"]
````

## 3. 速度判据必须转回机体系

速度跟踪的判据用机体系速度。随机出生带随机 yaw，即使策略完美行走，全局 $x$ 速度对不同朝向求平均也接近 0，用它会得出"原地不动"的错误结论。离线评估把世界系速度按 yaw 转回机体：

$$v^{body}_x = \cos\psi \, v_x + \sin\psi \, v_y,\qquad v^{body}_y = -\sin\psi \, v_x + \cos\psi \, v_y$$

跟踪误差取 $\|v^{body}_{xy} - v^{cmd}_{xy}\|$，与训练指令同空间（`sim/eval_walk.py:199-215`）。

这条判据与训练侧的指令坐标系是一对：训练若开 `--body_frame`（`train/train_go1.py:434-437`），评估也必须用机体系；训练用全局指令而评估用机体系速度，会得到系统性的偏差读数。

## 3.1 判据与训练侧的对应关系

三类判据各自对应训练侧的一处设置：速度判据对应指令坐标系，步态判据对应步态塑形项与抬脚参数，数值判据对应约束容量与求解器迭代。定位时先问"这个现象对应训练侧哪一处设置"，再去看那一处的取值，可以避免在无关的分项上反复试。

## 4. 步态质量的两个统计量

步态质量看四足占空比与对角同步率。占空比是单足接触时间占比，正常 trot 落在 0.37 到 0.80；对角同步率是 FR 与 RL 同时接触的帧占比，理想 trot 应超过 50%。这两个量能区分"真的在迈步"与"贴地滑行拿满速度分"。

| 判据 | 合理区间 | 出处 |
| --- | --- | --- |
| 四足占空比 | 0.37 到 0.80 | 实验记录 §11.3 |
| 对角同步率 | 大于 50% | 实验记录 §19 的目标 |
| 触地相足速比躯干速度 | 小于 0.3 | 实验记录 §11.3 |

三个判据要一起看。占空比 0.9 以上加触地相足端速度接近躯干速度，说明四足几乎一直贴地滑行：速度分拿满，步态完全不对。这类组合是"激励缺口"的典型特征，单看速度指标发现不了。

## 5. 数值问题的排查顺序

数值问题优先查非有限值和接触约束。MJX 的 `njmax` 是每个 world 的约束行数上限，`naconmax` 是全体 world 共享的接触槽总数。走路峰值约 4.8 接触每 world，起身躺地时约束更多。约束溢出后写入越界，`qacc` 与 `sensordata` 变 NaN，奖励跟着 NaN，PPO 参数被打爆。环境在 `step` 里对所有被读的字段做了有限性回填，并把 `done` 立即置位（`envs/go1_walk.py:939-954`）。

排查 NaN 时要区分配置问题与策略问题。固定动作序列下把 `naconmax` 调小会改变接触求和顺序，物理轨迹从第 1 步就分叉，不能用它做速度优化。这条在查看器脚本的注释里有实测记录（`sim/watch_v20_fast.py:31-36`）。

```mermaid
sequenceDiagram
  autonumber
  participant D as 调试者
  participant L as 固定动作序列
  participant E as Go1Walk
  participant P as 探针脚本
  D->>L: 冻结动作，固定 seed
  L->>E: 同一环境跑 N 步
  E-->>P: qpos qvel qacc reward
  P->>P: 统计非有限值与 done
  P-->>D: 溢出比例与触发步
  D->>D: 先改 njmax 复测，再谈策略
```

容量配置与求解器迭代是一对：迭代次数不足时约束求解不收敛，接触会出现异常大的冲量，同样能把状态推成非有限值。遇到 NaN 时这两项要一起看。

`envs/go1_walk.py:96` 是约束容量配置与 NaN 护栏的默认值区，改容量先看这里。`sim/probe_nefc.py:59-82` 用 768 环境跑数百步，直接数 `qpos`、`qvel`、`qacc` 里的非有限值，可选加载策略或随机动作。

## 6. 离线评估的口径

`sim/eval_walk.py` 用固定 seed 20260915 与 512 环境，出生点与指令对不同检查点完全一致（`sim/eval_walk.py:35-36`）。评估环境打开地形、高度扫描、机体系指令与随机出生，关掉推挤与观测噪声，并把足端接触切回硬接触（`sim/eval_walk.py:132-152`、`sim/eval_walk.py:139`）。

输出分三组：存活率与 episode 长度、速度组（vx_body、跟踪误差、位移速度）、地形组（足下地面最大爬升与占比）。脚本用 `jax.jit(jax.vmap(...))` 包住 reset 与 step，按帧循环而非 eager 调用（`sim/eval_walk.py:159-161`）。

速度组里 `avg_path_len` 是世界系每步位移长度除以步数，等于平均位移速率；`avg_vx_body` 才是与指令同空间的量（`sim/eval_walk.py:228-239`）。评估与训练的接触模型不一致时，同一个策略在评估里掉点，容易被误判为泛化差。

## 7. 步态诊断与历史判据

步态统计看每腿占空比与对角同步。历史诊断脚本已不在当前检出，判据与实测数字保留在实验记录里：v18 的对角同步 70.8%、前腿占空比 49% 与 43%；v19 退化到对角同步 13.2%、前腿占空比 13% 与 17%。当前检出的 `sim/watch_v20_fast.py` 提供高帧率回放，可用来录步态序列，但不直接输出统计量。

诊断脚本缺失时，判据本身仍可用：把回放录成帧序列后按接触信号数占空比与同步率，或者直接在评估脚本里加一段统计。关键是判据先定好、口径统一，而不是每次按感觉描述步态。

## 8. 数值护栏覆盖哪些字段

`step` 里的有限性回填覆盖了奖励与观测会用到的字段：`qpos`、`qvel`、`qacc`、`qfrc_actuator`、`actuator_force`、`sensordata`、`site_xmat`，并把该步 `done` 置位（`envs/go1_walk.py:939-954`）。总奖励再做一次有限性查表（`envs/go1_walk.py:1028-1029`），配合下限截断（`envs/go1_walk.py:1030`）。

| 护栏 | 覆盖 | 作用 |
| --- | --- | --- |
| 状态字段回填 | qpos/qvel/qacc/力/传感器/site 姿态 | 防止非有限值污染观测与奖励 |
| 立即置 done | 该步终止 | 避免 NaN 环境继续被采样 |
| 奖励有限性查表 | total | 非有限奖励置 0 |
| 下限截断 | total | 负值抬升 |

四层护栏的顺序也重要：状态字段回填发生在奖励计算之前，所以奖励读到的是回填后的值；若回填放在奖励之后，奖励仍会吃到 NaN。这个顺序在改动 step 时容易被破坏。

护栏的作用是止损，不是修根因。它把"训练崩掉"变成"这一步被截掉"，如果 NaN 比例高，训练仍然学不到东西，只是不报错。

## 9. 交互观察的判据与回放

回放脚本与评估脚本是两份代码，判据要各自核对一遍：回放里的接触信号与评估里的接触统计可能因为接触模型档位不同而不可比。

查看器 `sim/view_go1.py` 的摔倒判据是逐帧计算并连续计数：`up_z` 低于 0.30、躯干离地低于 0.16 m，连续满足 18 帧才武装，冷却 50 帧，出界 5.8 m 直接重置（`sim/view_go1.py:275-298`、`sim/view_go1.py:883-885`）。看步态时应把指令按到 0，否则默认 0.5 m/s 会在 8 到 16 s 内走到地形边缘。

高帧率回放用 `sim/watch_v20_fast.py`。它把策略前向 jit 成常量 rng 的调用（实测 11.0 ms 降到 0.08 ms），默认启用 d3d12 渲染路径，并在开窗口前预热到稳态，避免前几百帧停在数百毫秒（`sim/watch_v20_fast.py:16-30`）。

## 10. 易错点与调试清单

| 易错点 | 现象 | 排查位置 |
| --- | --- | --- |
| 用全局速度当跟踪判据 | 随机 yaw 下平均速度接近 0，误判原地不动 | `sim/eval_walk.py:199-215` |
| 总奖励下限为 0 又加负项 | reward 恒 0，PPO 无梯度 | `envs/go1_walk.py:1030` |
| 忘开 `--body_frame` | 边转边走直接失控，直行正常 | `train/train_go1.py:434-437` |
| 相位奖励开了但相位没进 obs | 该项恒为 0，步态推不动 | `envs/go1_walk.py:1122-1128` |
| 腾空阈值留 1.0 s | 正常摆动落地倒扣，策略不敢抬腿 | `envs/go1_walk.py:176-181` |
| `njmax` 偏小 | 接触溢出后 NaN，episode 被护栏杀掉 | `envs/go1_walk.py:96` |
| 调小 `naconmax` 想提速 | 轨迹从第 1 步分叉，物理不再等价 | `sim/watch_v20_fast.py:31-36` |
| 用绝对 $z$ 判终止 | 高台出生即终止，地形一大就废 | `envs/go1_walk.py:774-776` |
| 评估与训练的接触模型不一致 | 同一个策略评估掉点，误判为泛化差 | `sim/eval_walk.py:139` |

调试清单：

1. 先跑 `sim/eval_walk.py --pkl` 拿到固定 seed 的速度、存活与爬升三组数。
2. 速度不达标时先查 `frame` 与指令语义，再查观测的缩放与截断。
3. 速度达标但步态差时查占空比与对角同步，再对步态项做单变量对照。
4. reward 恒 0 时先看负项权重是否压过正向预算，再看总奖励截断。
5. 出现 NaN 时先用固定动作序列复测，确认是否与 `njmax`、`naconmax` 相关。
6. 改动护栏或接触档位后，用同一份固定 seed 评估复跑，确认指标没有口径漂移。

## 11. 小结

### 核心概念

- 调试先定判据：训练日志的 reward 混了出生点，离线固定 seed 才可比。
- 速度判据必须用机体系速度，与训练指令同空间。
- 失败分口径、激励、数值三类，排查手段互不通用。
- 步态质量看占空比与对角同步，能区分迈步与滑行。
- NaN 先查约束上限，再看策略，且不要靠改接触容量提速。
- 护栏只止损，NaN 比例高时训练仍学不到东西。

### 设计权衡

| 取法 | 采用处 | 代价 |
| --- | --- | --- |
| 固定 seed 离线评估 | `eval_walk.py` | 覆盖的地形与初始状态有限 |
| 有限性回填加立即终止 | `step` | 掩盖真实数值问题，需要探针补齐 |
| 交互查看器逐帧判据 | `view_go1.py` | 阈值要按机器人标定，误触发与漏触发并存 |
| 高帧率回放单独脚本 | `watch_v20_fast.py` | 与主查看器两套代码，需同步维护 |

## 12. 练习

### 基础题

1. 打开 `envs/go1_walk.py` 的 `default_config()`，确定同时打开 `terrain`、`height_scan`、`feet_phase` 后 actor 与 critic 的观测维度，并说明训练启动日志里哪一行会打印这两个数。
2. `sim/eval_walk.py` 的速度统计为什么要按 yaw 把世界系速度转回机体系？若改用 `qvel[:, 0]`，随机出生与随机 yaw 下会得到什么错误结论？
3. 把 `reward_clip_min` 从 0 改成很大的负数（如 $-10^6$）后，走路训练可能出现什么现象？请从总奖励截断与 PPO 梯度两方面解释。

### 挑战题

4. 给定失败形态："离线评估 vx_body 接近指令，但四足占空比都在 0.9 以上，触地相足端速度接近躯干速度"。设计一组单变量对照，判断这是激励缺口还是策略能力不足，要求列出至少两组对照、统一口径的判据、每组预期现象与验证方式，并指出若两组都无改善时下一步先查什么。

5. 说明"有限性回填加立即终止"这条护栏会掩盖哪类问题，并设计一个探针把被掩盖的 NaN 比例量出来，给出要记录的字段与判据。
